# 2026-09-03 — Varias líneas de decoración por venta

## Contexto

Juan Camilo señaló que una sola prenda a veces lleva más de un estampado (ej. pedido 02: camiseta oversize con punto corazón adelante y estampado tamaño carta atrás) — el formulario de Ventas solo tenía un tamaño de estampado y un costo, así que no se podían sumar ambos costos de producción correctamente para esa venta.

## Construido

- **`supabase/migrations/0011_lineas_decoracion.sql`**: tabla nueva `order_item_decorations` (`order_item_id`, `print_size` nullable, `cost_cop`) — una fila por cada estampado/bordado de la prenda. `order_items.cost_cop` sigue existiendo pero ahora es la **suma** de esas líneas (calculada en la Server Action, no en SQL). `order_items.print_size` (el campo viejo, un solo tamaño) queda sin usar para ventas nuevas — ya no representaba bien "puede haber varios"; no se tocan los datos de ventas ya registradas.
- **`apps/admin/components/DecorationLinesField.tsx`** (nuevo, client component): reemplaza el único selector de tamaño + campo de costo por líneas repetibles — cada una con su propio tamaño (opcional, solo aplica a estampado; para bordado se deja "No aplica") y su propio costo manual, con botón "+ Agregar otra decoración" y "Quitar" por línea. Mismo criterio de siempre: el envío real sigue siendo un `<form>` normal a la Server Action, el JS de cliente solo maneja cuántas líneas se muestran.
- `apps/admin/app/ventas/nueva/actions.ts`: parsea las líneas pareadas por índice (`decoration_print_size[]`/`decoration_cost_cop[]` vía `formData.getAll`), valida cada una, suma el total para `order_items.cost_cop` — mismo campo que ya alimentaba la rentabilidad bruta del Dashboard y la cuenta por pagar automática al proveedor de producción, así que ningún cálculo aguas abajo tuvo que cambiar, solo empezó a recibir el número correcto.
- `apps/admin/app/ventas/[id]/page.tsx`: se agregó la columna "Costo producción" (antes `cost_cop` se consultaba pero no se mostraba en ningún lado) — muestra el total y, si hay más de una línea, el desglose debajo (ej. "Punto corazón: $5.000 + Carta: $12.000").

## Verificación

Verificado en vivo con Playwright, a nivel de UI **y** de base de datos: venta de prueba con 2 líneas (punto corazón $5.000 + carta $12.000) → confirmado visualmente "$17.000" con el desglose correcto en el detalle de la venta → confirmado por consulta directa a Supabase que `order_items.cost_cop = 17000` y que `order_item_decorations` tiene exactamente esas 2 filas con los valores correctos → todo borrado después (orden, item y líneas de decoración), cascada de borrado confirmada sin filas huérfanas.

`tsc --noEmit` y `pnpm build` limpios en admin.
